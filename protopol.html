CHAPITRE 00 — FONDAMENTAUX

Les objets en JavaScript

Avant de parler de pollution, il faut d'abord comprendre ce qu'est un objet en JavaScript. Tout commence là.

📦 Qu'est-ce qu'un objet ?

Un objet est un conteneur de données organisé en paires clé-valeur. C'est la structure de base la plus utilisée en JavaScript. Presque tout en JS est un objet : les tableaux, les fonctions, les dates, les regex...

bases-objet.js
// Créer un objet simple
const user = {
  name: "Alice",
  age: 25,
  role: "developer"
};

// Accéder aux propriétés
console.log(user.name);        // "Alice"
console.log(user["role"]);     // "developer"

// Ajouter dynamiquement une propriété
user.email = "alice@mail.com";

// Supprimer une propriété
delete user.age;

// Itérer sur les clés
for (let key in user) {
  console.log(key, "→", user[key]);
}
// name → Alice
// role → developer
// email → alice@mail.com

Le point crucial : en JS, quand vous accédez à une propriété qui n'existe pas sur un objet, JavaScript ne s'arrête pas là. Il va chercher plus haut dans la chaîne. C'est ici que la magie (et le danger) commence.

propriete-absente.js
const obj = { a: 1 };

console.log(obj.a);           // 1        ← existe sur l'objet
console.log(obj.b);           // undefined ← n'existe nulle part
console.log(obj.toString());  // "[object Object]"
// ↑ MAIS ATTENDEZ... on n'a jamais défini toString() !
// D'où vient cette méthode ? → Du PROTOTYPE.
CHAPITRE 01 — LE PROTOTYPE

La chaîne prototypale

JavaScript utilise un système d'héritage prototypal (et non classique comme Java/C++). Chaque objet possède un lien interne vers un autre objet appelé son prototype. Quand on accède à une propriété, JS la cherche d'abord sur l'objet, puis remonte la chaîne des prototypes.

┌──────────────────────────┐ │ votre objet │ │ { name: "Alice" } │ │ │ │ __proto__ ──────────────┼──┐ └──────────────────────────┘ │ ▼ ┌──────────────────────────────────────┐ │ Object.prototype │ │ toString(), hasOwnProperty(), │ │ valueOf(), constructor, ... │ │ │ │ __proto__ ──────────────────────────┼──┐ └──────────────────────────────────────┘ │ ▼ null (fin de chaîne)
🔗 Règle fondamentale

Quand vous faites obj.propriété, JavaScript exécute cet algorithme :
1. Est-ce que obj a directement cette propriété ? → Si oui, retourne la valeur.
2. Sinon, est-ce que obj.__proto__ l'a ? → Si oui, retourne la valeur.
3. Sinon, est-ce que obj.__proto__.__proto__ l'a ? → Continue à remonter...
4. Si on arrive à null → retourne undefined.

prototype-demo.js
const animal = { type: "unknown", speak() { return "..."; } };
const dog = Object.create(animal);  // dog hérite de animal
dog.name = "Rex";

console.log(dog.name);    // "Rex"     ← propre à dog
console.log(dog.type);    // "unknown" ← hérité de animal
console.log(dog.speak()); // "..."     ← hérité de animal

// Vérifier la chaîne
console.log(dog.__proto__ === animal);                 // true
console.log(dog.__proto__.__proto__ === Object.prototype); // true
console.log(dog.__proto__.__proto__.__proto__);             // null

Il y a 3 façons d'accéder au prototype d'un objet, et c'est important pour comprendre les vecteurs d'attaque :

acces-prototype.js
const obj = {};

// Méthode 1 : __proto__ (non-standard mais universellement supporté)
obj.__proto__                     // → Object.prototype

// Méthode 2 : Object.getPrototypeOf() (standard ES5+)
Object.getPrototypeOf(obj)       // → Object.prototype

// Méthode 3 : via constructor
obj.constructor.prototype        // → Object.prototype

// Les 3 pointent vers le même objet !
obj.__proto__ === obj.constructor.prototype  // true
💡 __proto__ vs prototype

Ne confondez pas les deux : __proto__ est une propriété de chaque instance (le lien vers son prototype). prototype est une propriété des fonctions constructeur (le modèle pour les futures instances). Quand vous faites new Foo(), l'objet créé aura __proto__ === Foo.prototype.

Et voici le point crucial : Object.prototype est partagé par TOUS les objets créés avec {} ou new Object(). Si vous modifiez Object.prototype, vous modifiez le comportement de tous les objets de votre application.

pollution-basique.js
// AVANT la pollution
const a = {};
const b = {};
console.log(a.hacked);  // undefined
console.log(b.hacked);  // undefined

// ☠️ On modifie Object.prototype
Object.prototype.hacked = "pwned";

// APRÈS la pollution — TOUS les objets sont affectés
const c = {};
console.log(a.hacked);  // "pwned" ← existait avant !
console.log(b.hacked);  // "pwned" ← existait avant !
console.log(c.hacked);  // "pwned" ← créé après !
CHAPITRE 02 — LA VULNÉRABILITÉ

Comment la pollution se produit

Un attaquant ne peut pas directement écrire Object.prototype.x = y dans votre serveur. Il a besoin d'un vecteur : une fonction dans votre code qui va involontairement écrire sur le prototype en traitant des données contrôlées par l'attaquant.

🎯 Les 3 conditions nécessaires

Pour qu'une prototype pollution soit exploitable, il faut :
1. Une fonction qui effectue une assignation récursive de propriétés (merge, clone, extend, defaultsDeep...)
2. Cette fonction ne filtre pas les clés spéciales (__proto__, constructor, prototype)
3. L'entrée provient d'une source contrôlée par l'attaquant (body HTTP, query params, JSON...)

Regardons la fonction de merge la plus classique et pourquoi elle est vulnérable :

vuln-merge-explained.js
// ❌ Fonction de merge vulnérable — très courante dans le code réel
function merge(target, source) {
  for (let key in source) {
    //       ↑ Itère sur TOUTES les clés, y compris "__proto__"
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (typeof target[key] !== 'object') {
        target[key] = {};
      }
      merge(target[key], source[key]);
      //   ↑ Quand key === "__proto__", target[key] === Object.prototype !
      //     On merge donc DANS le prototype !
    } else {
      target[key] = source[key];
    }
  }
}

// Quand l'attaquant envoie ce JSON :
const malicious = JSON.parse('{"__proto__": {"isAdmin": true}}');
//                                 ↑ JSON.parse crée un objet avec la CLÉ "__proto__"
//                                   (pas un lien prototypal, une vraie propriété !)

Le point subtil : JSON.parse('{"__proto__":{}}') crée un objet où __proto__ est une propriété propre (own property). Mais quand le code fait target["__proto__"] en lecture, JavaScript interprète ça comme l'accès au prototype réel, qui est Object.prototype. C'est cette ambiguïté qui crée la vulnérabilité.

Voici le déroulement pas à pas de l'attaque :

01

L'attaquant envoie un payload

POST /api/settings avec body : {"__proto__": {"isAdmin": true}}

02

Le serveur parse le JSON

JSON.parse(body) crée un objet avec __proto__ comme clé propre. À ce stade, aucun danger.

03

La fonction merge traite l'objet

Elle itère sur les clés et tombe sur "__proto__". Elle fait target["__proto__"] qui renvoie Object.prototype (le vrai prototype).

04

La propriété est écrite sur le prototype

Le merge continue et fait Object.prototype["isAdmin"] = true. La pollution est effective.

05

Tous les objets sont affectés

Désormais, n'importe quel {}.isAdmin retourne true. Si le code fait if (user.isAdmin), c'est un bypass total.

💡 Variante : constructor.prototype

Si __proto__ est filtré, l'attaquant peut utiliser le chemin alternatif : {"constructor": {"prototype": {"isAdmin": true}}}. Car obj.constructor pointe vers la fonction Object, et Object.prototype est le même objet cible.

CHAPITRE 04 — EXPLOITATION PYTHON

Class Pollution en Python

Python n'a pas de prototypes, mais un système de classes tout aussi exploitable. Les objets Python ont des attributs spéciaux (dunder attributes) qui permettent de remonter la hiérarchie des classes et d'accéder à des objets normalement inaccessibles.

🐍 Attributs spéciaux exploitables

__class__ → la classe de l'instance
__base__ / __bases__ → la/les classe(s) parente(s)
__subclasses__() → toutes les sous-classes
__init__ → le constructeur (c'est une fonction)
__globals__ → les variables globales du module de la fonction
__dict__ → le dictionnaire d'attributs de la classe

python-class-basics.py
# En Python, les classes sont des objets MUTABLES
# On peut modifier les attributs de classe à la volée

class User:
    is_admin = False
    can_delete = False

alice = User()
bob = User()

print(alice.is_admin)  # False
print(bob.is_admin)    # False

# ☠️ Pollution via __class__
# Modifier un attribut de classe affecte TOUTES les instances
alice.__class__.is_admin = True

print(alice.is_admin)  # True  ← modifié directement
print(bob.is_admin)    # True  ← POLLUÉ aussi !

# On peut même remonter plus haut
class Admin(User):
    pass

admin = Admin()
# admin.__class__.__base__ === User
# admin.__class__.__base__.__base__ === object
# On peut polluer N'IMPORTE QUELLE classe parente
instance (alice) │ ├── __class__ ──→ User │ │ │ ├── __base__ ──→ object │ │ │ │ │ └── (toutes les classes héritent d'object) │ │ │ ├── __dict__ ──→ {'is_admin': False, ...} │ │ │ └── __init__ ──→ <function> │ │ │ └── __globals__ ──→ MODULE GLOBALS ! │ (SECRET_KEY, os, sys, app, ...)
python-vuln-merge.py
# ❌ Fonction merge vulnérable — pattern courant en Python
def merge(target, source):
    for key, value in source.items():
        # Si la valeur est un dict, on merge récursivement
        if hasattr(target, key) and isinstance(value, dict):
            merge(getattr(target, key), value)
        else:
            setattr(target, key, value)
            # ↑ setattr avec des clés non filtrées = DANGER

# L'attaquant envoie ce payload :
payload = {
    "__class__": {
        "__base__": {
            "is_admin": True,
            "can_delete": True
        }
    }
}

# Exécution :
# 1. merge(emp, payload)
# 2. key = "__class__" → getattr(emp, "__class__") = Employee class
# 3. Recurse: merge(Employee, {"__base__": {"is_admin": True}})
# 4. key = "__base__" → getattr(Employee, "__base__") = object class
# 5. Recurse: merge(object, {"is_admin": True})
# 6. setattr(object, "is_admin", True) → POLLUTION GLOBALE !

class Employee:
    is_admin = False

emp = Employee()
merge(emp, payload)

# Toutes les classes héritant d'object sont polluées
print(Employee.is_admin)  # True !

Vecteurs alternatifs et cas réels

// ═══ VECTEUR 1 : Query string (Express qs parser) ═══
// GET /search?__proto__[isAdmin]=true
// Le parser qs convertit ceci en objet avec __proto__
// Certaines versions de qs sont vulnérables

// ═══ VECTEUR 2 : path-based assignment ═══
function setPath(obj, path, value) {
  const keys = path.split('.');
  let current = obj;
  for (let i = 0; i < keys.length - 1; i++) {
    current = current[keys[i]];  // ← Vulnérable si keys[i] = "__proto__"

  current[keys.at(-1)] = value;

// setPath({}, "__proto__.isAdmin", true) → pollution !

// ═══ VECTEUR 3 : Object.assign() deep ═══
// Object.assign seul n'est PAS vulnérable (shallow copy)

CHAPITRE 07 — DÉFENSES

Se protéger efficacement

Connaître l'attaque c'est bien, savoir se défendre c'est mieux. Voici les techniques de protection classées par efficacité, du plus simple au plus robuste.

01

Filtrer les clés dangereuses

La défense la plus directe : bloquer __proto__, constructor et prototype dans toute fonction de merge/clone.

defense-01-filter.js
const BLACKLIST = new Set(['__proto__', 'constructor', 'prototype']);

function safeMerge(target, source) {
  for (const key of Object.keys(source)) {  // Object.keys = own properties only
    if (BLACKLIST.has(key)) continue;      // ← Skip dangerous keys
    if (source[key] && typeof source[key] === 'object' && !Array.isArray(source[key])) {
      target[key] = safeMerge(target[key] || {}, source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}
02

Utiliser Object.create(null)

Crée des objets sans prototype — immunisés contre la pollution car ils n'ont aucune chaîne prototypale.

defense-02-null-proto.js
// Objet normal : hérite de Object.prototype
const normal = {};
console.log(normal.__proto__);  // Object.prototype (pollutable)

// Objet sans prototype : immunisé
const safe = Object.create(null);
console.log(safe.__proto__);    // undefined (pas de chaîne !)

// Idéal pour stocker des données venant de l'extérieur
const userInput = Object.create(null);
Object.assign(userInput, JSON.parse(body));  // Sûr

// Aussi utile : Map pour les clés dynamiques
const safeMap = new Map();
safeMap.set("__proto__", "harmless");  // Stocké comme clé, pas comme proto
03

Geler le prototype

Object.freeze(Object.prototype) empêche toute modification. Attention aux effets de bord avec certaines librairies.

04

Validation de schéma

Utilisez une librairie de validation (Joi, Zod, ajv) pour n'accepter que les propriétés attendues. Rejetez tout le reste.

defense-04-schema.js
// Avec Zod (TypeScript/JS)
const { z } = require('zod');

const ProfileSchema = z.object({
  name: z.string().max(100),
  email: z.string().email(),
  theme: z.enum(['light', 'dark']),
}).strict();  // ← Rejette TOUTE clé non définie

// "__proto__", "constructor" → automatiquement rejetés
const result = ProfileSchema.safeParse(req.body);
if (!result.success) return res.status(400).json(result.error);
05

Défense Python : __slots__ et whitelist

En Python, utilisez __slots__ pour limiter les attributs et filtrez tout ce qui commence par _.

defense-05-python.py
# Technique 1 : __slots__ (empêche les attributs dynamiques)
class SafeUser:
    __slots__ = ('name', 'email', 'theme')
    # setattr avec autre chose → AttributeError

# Technique 2 : Whitelist stricte
ALLOWED_FIELDS = frozenset({'name', 'email', 'theme', 'language'})

def safe_update(target, data: dict):
    for key, value in data.items():
        if key not in ALLOWED_FIELDS:
            continue  # Ignore tout ce qui n'est pas dans la whitelist
        if key.startswith('_'):
            continue  # Double protection contre dunder attributes
        setattr(target, key, value)

# Technique 3 : Pydantic (validation de schéma Python)
from pydantic import BaseModel

class UserUpdate(BaseModel):
    name: str | None = None
    email: str | None = None
    # __class__, __proto__ etc. automatiquement rejetés

data = UserUpdate(**request.get_json())  # ValidationError si invalide
🏆 Résumé des défenses par priorité

1. Validation de schéma (Zod/Joi/Pydantic) — empêche le problème à la source
2. Whitelist de propriétés — n'accepte que ce qui est prévu
3. Filtrage de clés — bloque __proto__, constructor, prototype
4. Object.create(null) / Map — supprime le vecteur d'attaque
5. Object.freeze(Object.prototype) — dernière ligne de défense
6. Mise à jour des dépendances — corrige les CVEs connues
